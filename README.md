# normalize-chinese-prose

让 AI 在写中文或改中文时，能像个真正有经验的写作者那样下笔。

适用环境：Claude Code、OpenAI Codex、DeepSeek Harness 等支持 `agents/skills` 约定的 Agent。

---

## 一、设计理念：去欧化与去 AI 味

用大模型写中文或改中文，最根本的毛病集中在两点：**欧化句法**与 **AI 腔调**。

### 1. 去欧化（追求通、简、洁）
现代书面语受外语（英、日）翻译腔侵蚀严重，模型生成时尤其泛滥：
- **多层“的”长定语**：在中心词前面压两三层不同维度的修饰，主干读不到位；
- **万能动词包装**：“对……进行分析”、“作出……贡献”、“开展……工作”，用虚动词搭配抽象名词；
- **非必要被动句**：滥用“被认为”、“被广泛应用于”，削弱中文的主动和流水神韵；
- **从句语序倒置**：直译英语的 when、if，写出“当……的时候”、“在……的情况下”。

去欧化不是反对一切外来语法，而是清理那些**不承载有效信息、纯粹增加读者认知负担的翻译腔外壳**。

### 2. 去 AI 味（打破模板与防御性对冲）
模型经过对齐训练后，形成了顽固的文风指纹：
- **防御性负描述（假想敌对冲）**：不管读者有没有误解，逢观点必先退三步（“本方案不追求……也不试图……而是……”、“这并不意味着……更不代表……”）；
- **相邻句句法骨架同款**：连着两三句逗号位置一样、成分顺序一样、收尾节奏一样，整齐得像在填表格；
- **空心框架**：总分总模板、现状—问题—对策三段式、满篇冒号列表撑版面、结尾强行升华。

去 AI 味的核心动作是**“非必要不立反面，直接给出正面断言”**，并打散相邻句的同构句法，让事实推进取代空转的结构套路。

### 3. 履职先于语体
判据分两层：**先问这句在这个文体里履职了没有，再问它像不像好中文。**
- 合同条款的防御性冗余不是同义反复；
- 技术规范和法律条文的长限定是在定义义务标的，不能轻易拆散；
- 学术讨论的审慎克制不是无判断落点。

第一层过了就别轻易动。“判定不改”是正当结论，起笔起草时也必须以文体履职为第一优先级。

## 二、理论依据与学术观点

本技能不是凭个人好恶列清单，其判据与边界建立在明确的语言学与实证研究之上：

### 1. 欧化维度的学术支撑
- **余光中《怎样改进英式中文？——论中文的常态与变态》**（1987）：欧化轴的核心参照。提供可替换性测试（能说“名气”就别造“知名度”）、一“的”一义、万能动词替换和二二双音节节奏等具体操作法。
- **王力《中国现代语法》**：界定欧化主要发生在书面语（文法上欧化而非口语语法欧化），明确“汉语从句本来少，靠流水小句推进”。
- **吕叔湘、朱德熙**：关于汉语流水小句、意合特征与现代汉语规范的论述。朱德熙指出“一种说法得到社会普遍承认才有合法性”，作为演进尺度（哪些欧化已沉淀不该动）的判定基础。
- **贺阳《现代汉语欧化语法现象研究》**：指出欧化受语体制约，正式语体受冲击最深，推翻了“公文/学术文体因庄重所以可以保留翻译腔”的借口。

### 2. AI 味与话语分析的实证研究
- **杨林秀、平嘉鹏（《当代修辞学》2024 年第 6 期）**：基于元话语（Metadiscourse）分析框架，指出大模型在学术语篇中表现出显著的态度标记匮乏与对冲语（Hedges）过度避险，高频依赖程式化的“否定平行结构”（Negative Parallelism）来规避断言责任。这是治理“负描述/假想敌”的直接学理依据。
- **朱君辉、王萌岩等（《中文信息学报》）**：大模型生成文本存在显著的“统计均质化”与“模式化对称支架”，语法树扁平对称，缺乏人类写作的直接断言与事实跳跃。
- **吴继峰、胡韧奋、彭一平（《语言文字应用》2025 年第 4 期）**：大模型生成的学术汉语词汇抽象性和多样度更高，但句子更短、句法树层级更浅、依存距离更短。表明治理 AI 味不能一味把长句切短，而是要治理无信息的修饰嵌套与表层衔接。
- **崔希亮、赵霞（《当代修辞学》2024 年第 3 期）**：明确将大模型语言问题界定为修辞学问题，强调从篇章、认知与交际意图层面系统性治理，而非单纯的敏感词替换。

### 3. 法规与国家标准分层
- **法律强制层**：按《国家通用语言文字法》（2025 年修订，2026-01-01 施行），针对出版物、信息技术产品及公共服务平台文案，严格遵循规范汉字与外文加注义务；
- **推荐性标准层**：GB/T 15834（标点符号）、GB/T 15835（数字用法）、GF 1001（第一批异形词整理表）；
- **无成文规范层**：句法、修辞、欧化与 AI 味，只判通不通、简不简、洁不洁，不以法规越界裁定。

## 三、基本架构

技能由入口文件与 8 个专业参考模块构成：

```text
normalize-chinese-prose/
├── SKILL.md            # 技能主入口：立场、三大守恒红线、七步撰写/改写工作流、四项读法、七大动作
├── LICENSE             # MIT 许可证
├── README.md           # 使用说明
└── references/
    ├── craft.md        # 动作库（拆/换/删/并/主/缀/正/填）、九大文本族、反开脱五问与 12 条反例警戒
    ├── models.md       # 正面特征库、虚字手感、句式库、正面界定表、正向自查七问与分族豁免
    ├── norms.md        # 完整理论与规范依据：现行法律国标条款、学者学说、人机语言特征实证文献
    ├── symptoms.md     # 症状速查表（结构层、句法层、字法层、词层、文字层）
    ├── cases.md        # 34 组带一手文献出处的病例对照与改法理由
    ├── examples.md     # 13 类文体整段示范（技术报告、公文、学术论文、合同等）
    ├── samples.md      # 26 段 1949 年后真实发表范文的实测分析
    └── corpus.md       # 语料库总目与登记册（逐条标定四级置信度 ◎○△▽）
```

### 核心动作与规则
- **七大动作**：拆（后置长定语）、换（本字动词）、删（空框架与虚字）、并（错开相邻同款骨架）、主（还原主动）、缀（一“的”一义）、正（正面界定替代负描述）。
- **四项读法**：复述测试（查空话）、朗读测试（查语气起伏）、具体项测试（查可核验事实）、假想敌测试（查防御性负描述）。
- **三大守恒红线**：信息守恒（数字、单位、专名、法律情态词不丢）、证据强度守恒（推测不改确定）、不添事实（未给出的数据进存疑清单向作者确认，严禁脑补）。

## 安装与使用

克隆到本地通用或特定 Agent 技能目录：

```bash
# 通用 Agent 技能目录
git clone https://github.com/Zessi-C/normalize-chinese-prose.git ~/.agents/skills/normalize-chinese-prose

# 或 Qoder 工具目录
git clone https://github.com/Zessi-C/normalize-chinese-prose.git ~/.qoder-cn/skills/normalize-chinese-prose
```

支持该约定的 Agent 会自动加载。在对话中要求“写一段方案”、“起草公文”、“去 AI 味”、“顺一下中文”或“写得像行家一点”时，直接生效。
